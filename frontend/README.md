# QNetra Frontend

The presentation layer for QNetra — Enterprise Cryptographic Discovery & Analysis Tool.

Its job is to turn the output of the analysis pipeline into a security investigation experience:
what cryptography exists, where it is, how exposed it is, how urgent migration is, what to migrate
to, and — always — the evidence behind each of those conclusions.

---

## The one rule

**The frontend implements no security logic.**

Risk scores, quantum classification, the Mosca inequality, PQC selection, CBOM generation and
confidence scoring are all produced by `core/` and reach the interface through the API. The
frontend sorts, filters, searches, groups, paginates, formats and explains. It does not decide.

Where the backend cannot produce something, the UI says so (`<Unavailable>`) instead of filling
the space with a number. `API_GAPS.md` records every one of those places.

## Running it

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # type-check + production build
npm run lint
```

### Data sources

The Phase 4 API gateway (`backend/`) is not implemented yet, so the app ships with two transports,
selected by `VITE_API_MODE` (see `.env.example`):

| Mode | Behaviour |
| :--- | :--- |
| `mock` *(default)* | Serves `src/mocks/fixtures/`, generated by running the **real** pipeline over `samples/`. Speaks the same request contract as the live API. |
| `live` | Talks to the FastAPI gateway at `VITE_API_BASE_URL` (default `/api/v1`, proxied to `http://127.0.0.1:8000` in dev). |

Switching is configuration only — no component knows which transport is in use.

Regenerate the offline dataset from the current engines at any time:

```bash
python frontend/tools/generate_fixtures.py
```

Every value it writes comes from `scanners/` and `core/`. Nothing is authored by hand.

## Design system

Defined entirely in `src/styles/tokens.css`. Premium enterprise security tooling: a near-black
foundation, graphite surfaces, hairline borders, one restrained blue accent, and semantic colour
used **only** where it carries meaning the backend assigned.

- **Type** — Inter for the interface, JetBrains Mono for anything technical (algorithms, paths,
  identifiers, parameters). Both are bundled, not fetched from a CDN, so the product works in
  restricted and air-gapped networks.
- **Spacing** — a 4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 80 scale. Conceptual areas are
  separated by large space and a hairline, never by nesting more boxes.
- **Components** — cards are used only where they group something. Metrics, distributions and
  explanations sit in open content separated by rules.
- **Severity colour** — `data-sev` on any element resolves `--sev`, `--sev-wash` and
  `--sev-border`, so a badge, a bar and a number all agree without bespoke classes.
- **Motion** — 150–300 ms, hover and disclosure only, and it respects `prefers-reduced-motion`.

Pages are long on purpose. The brief is to reduce visual noise, not information.

## Progressive disclosure

The primary page states conclusions. Detail lives one interaction deeper:

```
Risk verdict → asset row → investigation drawer → classification → risk factors
             → Mosca terms → recommendation → supporting findings → source excerpt
```

The asset drawer joins the four engine views of one asset by `asset_id` and shows each engine's
own rationale, assumptions and limitations verbatim. `CodeEvidence` renders `location.snippet`
exactly as the API supplied it — the frontend never opens or parses a source file, and it only
prints line numbers where `start_line` is unambiguous.

## State handling

These states are kept distinct and never conflated:

| State | Treatment |
| :--- | :--- |
| No scan | Landing state with the scan entry point |
| Scan queued / running | Stage tracker; analysis views say the pipeline has not reached them |
| Scan failed / cancelled | Explicit failure with the recorded errors |
| Completed, nothing found | "No cryptographic artifacts detected" — a real result, not an error |
| Filtered to empty | "No rows match these filters", with a way to clear them |
| Backend cannot compute it | `<Unavailable>` with the reason and the endpoint that would serve it |
| API error | Structured code + message + retry |
